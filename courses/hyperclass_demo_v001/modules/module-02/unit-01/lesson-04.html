Start from a trusted bookmark. Confirm the network and asset before you touch any form fields.

Your wallet publishes the signed payload to peers. It sits in the mempool until a block includes it.

Nodes check signatures, balances, and protocol rules. Invalid work is dropped without drama.

Code walkthrough · terminal · nav bottom-left

We start with a plain object that describes what we want to send. No network call yet — just data you can inspect.

// Step 1 — shape the intent before signing
const transfer = {
  asset: "ETH",
  network: "mainnet",
  to: "0xabc…",
  amount: "0.05",
};

Ask the provider for a fee suggestion. Surface it in the UI so the learner sees cost before commitment.

// Step 2 — quote a fee the user can refuse
const fee = await estimateFee(transfer);
console.log("max fee", fee.max);
if (fee.max > budget) {
  throw new Error("fee too high");
}

Signing proves authority without revealing the private key to the dapp page. Keep this step explicit and cancellable.

// Step 3 — user gesture required
const signed = await wallet.sign({
  ...transfer,
  fee,
});
// signed.raw is opaque hex — never edit by hand

Push the signed payload to the network, then poll (or subscribe) until you see a confirmation depth you trust.

// Step 4 — publish, then verify on an explorer
const hash = await broadcast(signed.raw);
await waitForConfirmations(hash, 3);
echo "settled:", hash;
Process steps · rail + detail

Asset, network, amount, and destination address — write them down before opening the wallet.

Use a dry-run or a tiny test transfer when the destination is new or the amount is large.

Read fee, total debit, and any approval scope. Cancel if anything looks unfamiliar.

Approve only when the preview matches your notes. Record the tx hash for follow-up.
